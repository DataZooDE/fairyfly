## Next optimization targets from the measurements

1. Prefer one guarded batch for a known multi-step SAP path. The connected client comparison shows a large repeatable gap between three agent-selected calls and one batch, while the local HTTP route and queue add virtually no time in the uncontended case.
2. Keep model-visible reads compact. Summary mode and short screen refs reduce output substantially, especially on the 46-field Create Organization form. The next client catalog update should expose the new options so an agent can exercise them directly and report actual input tokens.
3. Investigate the owner identity postcheck after a navigation action. It adds about 2.2–2.5 seconds to BP transaction start and dominates that item's post-invocation time. Any optimization must preserve the current fail-closed session identity check; a worker-supplied post-action facts snapshot may avoid a separate probe, but this has not been implemented or validated.
4. Keep HTTP serialization low priority for this workflow. Admission, queue, and serialization were around 0–1 ms each in the measured uncontended requests. Model-specific latency and tokens require client-side usage telemetry; this environment did not expose them.
