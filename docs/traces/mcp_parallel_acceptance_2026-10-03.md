## Remaining deployment evidence

- Run two owner endpoints under separate interactive Windows accounts on a managed multi-user host and verify that neither endpoint lists, attaches or operates the other's SAP GUI windows. This host currently provides only one authenticated interactive account for the live test. `tests/integration/mcp_cross_account_isolation.ps1` now probes filtered lists, own and guessed-ID reads, cross-owner token rejection and explicit foreign-session attach denial using separate `session.attach` tokens. Its live mode requires local HTTP.sys URL-to-tray-PID association, the expected executable path, distinct interactive Windows owner SIDs, and unchanged per-user saved-connection file hashes around the refused attach. It refuses non-loopback endpoints, so bearer tokens cannot be sent by this probe over remote plaintext HTTP. The seven offline HTTP fixtures are explicitly protocol-only and cannot report account isolation. See `tests/integration/README.md` for setup. The live cross-account gate remains unrun. Numeric IDs are endpoint-local, so the guessed-ID check alone is not proof of foreign-window denial; the distinct SAP GUI session paths are needed for the attach check.
- If a representative slow SAP backend operation is available, repeat the narrow server-wait gate through tray MCP. The exact one-day SM37 query on this host returned in 0.7 to 2.3 seconds and did not give a clear overlap measurement. The long MCP batch already proves cross-window progress for client-side GUI work.
- A SAP GUI-wide prompt was not reproducible with the safe test transaction. A session-modal F4 dialog did leave another window readable (426 ms after warm-up).
- JSON disconnect cancellation currently watches the HTTP connection through [`HttpWaitForDisconnectEx`](https://learn.microsoft.com/en-us/windows/win32/api/http/nf-http-httpwaitfordisconnectex). It is verified for a closed HTTP/1.1 socket; resetting one stream on a still-open HTTP/2 connection is not yet detected by that connection-level watcher. A request-level cancellation signal or streaming response check is needed before claiming per-stream cancellation.
- Owner-mode tray cleanup now runs every 30 seconds. It scans Credential Manager once, removes policy/lease/sticky-default state for definitively revoked, expired, rotated or deleted tokens, and prunes expired idle leases. Incomplete credential scans retain state. A live SAP window closed outside Fairyfly is still not proactively proven absent; its policy record persists until the token ends, a confirmed disconnect, or tray restart. Live window enumeration for that cleanup remains open.
- On 2026-10-04, the stored Bigfox credential restored a live A4H session as saved connection 4. The same tray then passed the cross-process revoke, rotate and delete lease probes in sequence. The live SAP window was left open; the temporary tray was stopped after remaining healthy through more than one 30-second cleanup interval.
